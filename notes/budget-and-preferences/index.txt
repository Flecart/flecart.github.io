2a:T6eb6,<p>We start from <strong>preferences</strong> what people want, and how to translate it into maths so that they can drive demand curves. This should be very similar to the Von Neumann-Morgestern notes. This is the utility function.</p>
<p>We have a different set of assumptions between different Morgestern things.</p>
<h4 id="axioms-of-preferences">Axioms of Preferences<a class="anchor" aria-hidden="true" hidden href="#axioms-of-preferences">#</a></h4>
<ol>
<li>Every consumer has a direct preference between the two so <span class="katex"><span class="katex-html" aria-hidden="true"><span class="base"><span class="strut" style="height:0.7719em;vertical-align:-0.136em;"></span><span class="mord mathnormal">a</span><span class="mspace" style="margin-right:0.2778em;"></span><span class="mrel">≤</span><span class="mspace" style="margin-right:0.2778em;"></span></span><span class="base"><span class="strut" style="height:0.6944em;"></span><span class="mord mathnormal">b</span></span></span></span> and things like that.</li>
<li><strong>Non satiation</strong>: this is a strong assumption, it works for money for example. More is better in this case.</li>
<li>Transitivity.</li>
</ol>
<p>We assume that preferences are given. But you can also start studying that too!</p>
<h4 id="indifference-curves">Indifference Curves<a class="anchor" aria-hidden="true" hidden href="#indifference-curves">#</a></h4>
<blockquote>
<p>it's the rate we are willing to trade-off one good for another</p>
</blockquote>
<p>I can exchange two slides of pizza and one cookie, or having two cookies, on my preference curve they are the same. This is a map to <em>how to choose between two or more goods?</em>.</p>
<ol>
<li>Consumers prefer <strong>higher indifference curves</strong>. This follows from the non-satiation argument.</li>
<li>Indifference curves are <strong>downward sloping</strong>. It follows also from non-satiation. If it goes upward sloping then having more would be the same for me, so this is not possible.</li>
<li>Indifference curves <strong>cannot cross</strong>, if so it would violate transitivity.</li>
<li>Only one curve for one point. this si <strong>completeness</strong>.</li>
</ol>
